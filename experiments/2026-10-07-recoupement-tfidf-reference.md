# Fiche préenregistrée : le chiffre du TF-IDF de référence (A, macro-F1 0,7202) se retrouve-t-il à l'identique en le recalculant deux fois ? (recoupement N36, mesure d'infrastructure)

Écrite le 07/10/2026 avant tout essai de cette fiche. Motif : les tests de charge du 07/10 (`20261007-044852-stress-tfidf-par-coeur`, `20261007-050906-stress-tfidf-libre-contre-epingle`) ont montré 11 % de pannes et un résultat silencieusement différent sur 120 essais réussis. Le chiffre de A (`20261004-002944-tfidf-variant-char-balanced`, 0,7202) a été calculé une seule fois, avant la découverte de l'instabilité ; la règle N36 demande de recouper les chiffres publiés.

- **question** : deux recalculs indépendants (deux processus fils) des cinq plis du TF-IDF caractères 3 à 5 à poids équilibrés, avec la même recette que `scripts/tfidf_variants.py char-balanced`, redonnent-ils les probabilités hors pli enregistrées dans `results/predictions/tfidf-variant-char-balanced.probs.npz` ?
- **référence** : les probabilités enregistrées par le run `20261004-002944-tfidf-variant-char-balanced` ; **variante** : aucune (même code, même données, même plis) ; seul l'état de la machine change.
- **jeux et découpage** : développement seulement (3 586 patients, clé `folds`), jamais le test scellé ; sorties dans un fichier de mesure, **sans écraser** les prédictions enregistrées.
- **métrique principale** : égalité binaire des probabilités (empreinte SHA-256 de `probs`) ; secondaires : écart absolu maximal, nombre de patients dont la classe prédite change, macro-F1 de chaque recalcul.
- **critère de décision** : « concorde » si les deux recalculs ont la même empreinte que l'enregistré ; « concorde aux flottants près » si l'écart absolu maximal est inférieur à 1e-9 et aucune classe ne change ; « diverge » sinon (alors le chiffre de A n'est plus tenu pour établi et la divergence est détaillée par pli). Une panne brute (segfault, TypeError) est comptée à part et l'essai est refait une fois (`retry_transient` pour les signatures connues seulement, segfault : un nouveau processus).
- **règle d'arrêt anticipé (N31)** : arrêt si la mémoire disponible passe sous 20 000 Mio (garde `run_guarded.sh`) ; sinon deux calculs complets.
- **budget** : environ 2 × 12 minutes de CPU (734 s au run d'origine), un processus à la fois, moins de 3 Gio de RAM, aucun GPU, aucune lecture hors du dossier.
- **prédiction** : concorde à l'identique (0,6) ; concorde aux flottants près seulement (0,2, nombre de threads différent) ; diverge (0,1) ; au moins une panne brute sur les deux calculs (0,3, compté à part).
