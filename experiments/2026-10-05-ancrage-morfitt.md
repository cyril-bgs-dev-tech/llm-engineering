# Fiche préenregistrée : ancrage sur un benchmark public à résultats publiés, MorFITT (RM-49, EXPLORE)

Écrite avant tout run sur MorFITT. Jeu : MorFITT (3 624 résumés d'articles biomédicaux français, 12 spécialités, multi-étiquettes ; train 1 514, validation 1 022, test 1 088 ; **licence CC BY-SA 4.0** lue sur le dépôt GitHub `qanastek/MORFITT` le 05/10/2026 ; données non patients ; téléchargées en local depuis `DrBenchmark/MORFITT`, 3,4 Mo, ignorées par git ; aucun coût).

- **question** : situer notre recette (CamemBERT-bio à recette mûre, TF-IDF caractères, mélange 50/50) par rapport aux résultats **publiés** sur le même jeu de test avec la même métrique (F1 pondéré) : l'écart est-il compatible avec une reproduction du CamemBERT-bio publié, et le mélange dépasse-t-il le meilleur résultat publié ?
- **références publiées** (F1 pondéré, jeu de test, tableau 3 de arXiv 2402.16689, lues par résumé automatique : **à vérifier dans le papier avant toute citation externe**) : CamemBERT-bio 67,53 ; DrBERT 68,70 ; DrLongformer-CP 71,95 (meilleur). La définition exacte de la métrique du papier (F1 pondéré sur les matrices d'étiquettes) est supposée égale à `sklearn.metrics.f1_score(average="weighted")` ; si elle diffère, la comparaison est invalide et le dit.
- **variantes** : (i) encodeur CamemBERT-bio, perte binaire croisée, tête de classification à 12 sorties, seuil fixe 0,5 (au moins une étiquette par exemple), entraîné sur le jeu d'entraînement seul ; **réglage sur la validation uniquement** : taux {3e-5, 5e-5, 1e-4} × époques {10, 20}, une graine (1000), choix du meilleur F1 pondéré de validation ; **cinq graines** (1000 à 1004) au réglage retenu ; (ii) TF-IDF caractères 3 à 5, un contre tous, régression logistique à poids équilibrés, C choisi sur la validation parmi {10, 100, 1000} ; (iii) mélange 50/50 de la moyenne des probabilités des cinq encodeurs et du TF-IDF. **Le jeu de test n'est évalué qu'une fois, avec la configuration retenue ; aucun réglage sur le test.** Code : `llmft.multilabel`, `scripts/morfitt_run.py`.
- **ordre** : exécuté **après l'ouverture du test scellé de PARHAF** (règle de `PROTOCOLE_V2.md` section 5 : le benchmark public se lit après l'ouverture, pour ne pas influencer le choix du système final) ; le lot attend le marqueur d'ouverture.
- **métrique principale** : F1 pondéré sur le jeu de test ; secondaires : F1 micro et macro ; IC 95 % par bootstrap de patients (2 000 répliques) ; moyenne et écart-type sur les cinq graines.
- **critère de décision** : « reproduction » si la moyenne des cinq graines de l'encodeur est à moins de 2 écarts-types de nos graines du CamemBERT-bio publié (67,53) ; « au-dessus du publié » pour un système si la borne basse de son IC 95 % est supérieure à 71,95 (meilleur publié) ; « dans la bande du publié » si l'IC contient 71,95 ; « sous le publié » si la borne haute est sous 67,53. Les résultats publiés n'ont pas d'intervalle ici : la comparaison est ponctuelle et le dit.
- **budget** : environ 15 minutes de GPU (6 runs de réglage, 5 graines) et quelques minutes de processeur ; aucun coût externe.
- **prédiction** : moyenne des cinq graines de l'encodeur entre 64 et 72 (probabilité 0,75), compatible avec une reproduction du CamemBERT-bio publié (0,55) ; mélange 50/50 supérieur à l'encodeur seul (0,6) ; mélange « au-dessus du meilleur publié » (0,2).
