# Erratum à l'ADR-016 (06/10/2026), issu de la revue indépendante (P5-10)

L'ADR-016 est figée et hachée : elle n'est pas modifiée. Cet erratum corrige ou précise trois énoncés, sans changer le système gelé ni le résultat du test scellé.

1. **« Tous les textes, développement et test, ont la même fin, un saut de ligne »** : vérifié sur les 3 586 textes de développement (3 586 sur 3 586, run `tokenizers-passes-non-epinglees-identite`), **non vérifié séparément sur les 633 textes du test** ; l'énoncé sur le test est une hypothèse. Le risque de fragilité du LoRA à la fin du texte (cf. `RESULTATS.md`) ne peut donc pas être déclaré écarté pour le test : le résultat du test (G 0,8131) a été produit avec les textes tels quels, sans correction.
2. **« Aucun run passé n'est touché » par le contournement du tokenizer (Q24)** : la preuve d'identité repose sur 18 passes non épinglées sans plantage (2 dans `tokenizer-identite-sous-processus-epingle`, 16 dans `tokenizers-passes-non-epinglees-identite`), toutes identiques au sous-processus épinglé, et sur le fait que les 25 échecs observés le 05/10 ont été des plantages, pas des sorties corrompues. Les prédictions du temps A et les modèles finaux de la nuit du 05/10 (avant la garde) n'ont pas été re-tokenisés pour comparaison directe : l'énoncé devient « aucune divergence observée sur 18 passes ; comparaison directe des runs passés non faite ». Note : le taux de plantage observé le 05/10 (25 sur 31) ne se reproduit pas le 06/10 (0 sur 18) : la cause (course entre threads) reste une piste.
3. **Précondition « répétition générale enregistrée »** de `scripts/sealed_evaluation.py` : elle ne vérifiait pas le système ni le gel (un glob sur le nom du run). Le run de répétition utilisé pour l'ouverture est `20261006-182842-repetition-generale-temps-b` (système G, référence du gel) ; la précondition est durcie après coup (voir le commit qui l'accompagne), sans effet sur l'ouverture déjà faite.

Autres limites déclarées par la revue et non corrigées par cet erratum : le garde du test scellé empêche une seconde ouverture par le chemin normal mais pas un contournement volontaire (appel direct des fonctions, suppression du marqueur) ; `full_frame()` charge les étiquettes avant l'écriture du marqueur dans le script (aucune fuite effective constatée). Rapports : `docs/revue_independante/`.
